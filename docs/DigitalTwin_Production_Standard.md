# 통신설비 디지털트윈 제작 표준 (현행화 → 도면 → 점검 결과 연계)

> 대상: kt MOS 북부 사업혁신팀 고객지원파트 · 현장 조사자 · 트윈 등록 담당자
> 도구: `ICT_Twin_ADMIN_6.html` (오프라인 단일 파일) → 툴바 「현행화 ▾」

---

## 1. 상위 목표 (High-level Goal)

| 항목 | 내용 |
|---|---|
| 목적 | 현장에서 **실제로 확보할 수 있는 자료만으로** 설비의 위치·연결·상태를 2D/3D 트윈에 올리고, 점검 결과서를 올리면 **대시보드와 트윈 설비에 바로 연결**되게 한다 |
| 최종 수령인 | 팀장·관리자(현황 보고), 현장 담당자(점검·장애 대응), 고객사(설비 현황 공유) |
| 현업 활용 | ① 설비 위치·연결 계통 한눈에 확인 ② 점검 결과(불량·주의) 설비 단위 표시 ③ 장애 시 영향 범위 확인 ④ 라이저도·개통도 문서화 |
| 성공 기준 | 모든 설비가 실(방)에 배치되고 · 명판 기준 모델명이 확인되며 · 점검 측정값이 설비ID로 100% 연결됨 |

## 2. 입력 데이터 (답안지 · 필수 항목)

### 2-1. 설비 현행화표 — 7개 열 고정
`설비명 | 규격(모델명) | 수량 | 제조사 | 설치 위치 | 설치연도 | 비고`

- 설치 위치는 **「건물 + 층 + 실」** 순서로 적습니다. 예: `본관 7층 EPS실`, `북관 B1층 방재실`
- 모르는 값은 추측하지 말고 `확인불가`로 적습니다 (빈 값으로 처리되고 「검증」에서 누락으로 표시됨)

### 2-2. 현장 사진 조사 — 설비 1대당 최소 2장
| 순서 | 구분 | 촬영 기준 | 표준 파일명 |
|---|---|---|---|
| ① | 설비 전경 | 설비 전체가 한 장에 (랙이면 전면 전체, 문 열고) | `설비ID_01_전경.jpg` |
| ② | 명판 | 모델명·S/N·제조사 글자가 읽히게 정면 근접, 반사 없이 | `설비ID_02_명판.jpg` |
| ③ | 모듈 모델명 | 카드·모듈 표기마다 1장 (최대 8장) | `설비ID_03_모듈-n.jpg` |

- 앱에서 설비별 **📷 버튼 → 촬영**(휴대폰은 바로 카메라)하면 파일명이 자동으로 붙습니다.
- 명판의 모델명·S/N을 옮겨 적고 **「명판 대조 완료」**를 체크합니다. 읽히지 않으면 비워 둡니다.

### 2-3. 도면 확보 — 우선순위
1. **PDF 도면** (건축·통신 준공도) → 그대로 올림, 페이지 선택
2. **대피 안내도 / 종이도면 사진** → 정면에서 촬영, 네 모서리가 다 나오게
3. **도면 없음** → 「자동 작도」: 설치 위치 기준으로 층마다 실·복도·계단실을 만들고 설비를 배치 → 라이저도·개통도 자동 작성
- 축척: 길이를 아는 구간 1개(복도 길이, 벽 치수, 표준 문 폭 약 900mm)를 2점 클릭 + mm 입력

### 2-4. 점검 결과서 — 형식 무관, 표만 있으면 됨
| 형식 | 처리 |
|---|---|
| 엑셀 xlsx·csv | 시트 그대로 |
| 워드 docx | 문서 안의 표 (병합 셀 자동 채움) |
| PDF | 글자 위치로 표 복원 (스캔 이미지 PDF는 불가) |
| 한글 HWP · 구형 xls/doc | PDF 또는 xlsx/docx로 저장 후 |

필요한 열: `건물 · 층 · 점검 위치 · 설비 · 측정 항목 · 측정값 · 단위 · 기준 · 판정` (없는 열은 기본값으로 지정, 「본관 7층 EPS실」처럼 한 칸에 적힌 위치는 자동 분리)

## 3. 제약 조건 (제외할 것)

- **추측값 금지**: 모델명·연결·판정을 추정해서 채우지 않습니다. 비어 있으면 「누락」으로 표시합니다.
- 측정값은 **숫자만** 등록하며, 숫자가 아닌 값(측정불가 등)은 제외되고 「변환검증」 시트에 사유가 남습니다.
- 판정은 `양호 / 불량 / 주의 / 해당없음` 4가지로 통일합니다 (적합→양호, 부적합→불량 자동 변환, 빈칸→해당없음).
- 연결은 **확인된 것만** 등록합니다. 자동 규칙은 「같은 층 OFD → 광중계기·RU」 하나뿐이고, 층간 연결은 수동으로 추가합니다.
- 외부 인터넷 없이 동작합니다 (PDF 엔진·한글 문자표 내장). 사진·초안은 작업 브라우저에만 저장되므로 **JSON 백업 + 사진 ZIP**으로 보관합니다.

## 4. 제작 파이프라인 (단계별 검증)

```
[1단계 구조화]                 [2단계 검증]                  [3단계 산출·등록]
현행화표 붙여넣기  ──┐         누락 점검(⑤ 검증)            ADMIN 등록용 엑셀
현장 사진·명판     ──┼─▶ 초안 ─▶ 사진·명판·모델명·배치 ──▶  라이저도·개통도 PNG/SVG
도면(PDF/사진/자동) ─┘         결과서 변환검증               현장 사진 ZIP
                                                            점검 결과 → ADMIN 측정 → 대시보드
```

| 단계 | 앱 위치 | 완료 기준 (✔가 모두 켜져야 다음 단계) |
|---|---|---|
| ① 현행화·사진 | 간이 현행화 모드 ① | 설비 수 = 현행화표 수량 합계, 설비별 📷 전경·명판 |
| ② 도면 확보 | ② | 층마다 도면 또는 자동 작도, 축척 맞춤 완료 |
| ③ 실 그리기 | ③ | 설비가 있는 모든 층에 실 |
| ④ 설비 배치 | ④ | 배치 n/n |
| ⑤ 검증·내보내기 | ⑤ | 검증 8개 항목 ✔ → 엑셀 내보내기 |
| ⑥ ADMIN 등록 | 데이터 관리 → 엑셀 등록 | 「검증 완료」 → 전체 교체 적용 |
| ⑦ 점검 결과 연계 | 현행화 ▾ → 점검 결과서 변환 | 등록 가능 행 · 설비 연결 n/n → 「ADMIN 측정 등록으로 보내기」 → 점검일 선택 → 교체 |
| ⑧ 확인 | 현행화 ▾ → 측정 매칭 확인 / 라이저도·개통도 | 미매칭 0 |

## 5. 출력 포맷 · 명명 규칙

| 산출물 | 파일명 | 비고 |
|---|---|---|
| ADMIN 등록 엑셀 | `ICT_Twin_Quick_YYYYMMDD.xlsx` | 01~06 표준 시트 + 현행화표_원본 + 현장사진_목록 |
| 측정 엑셀 | `ICT_Twin_Measure_YYYYMMDD.xlsx` | 측정값 데이터 + 트윈연결(설비ID) + 변환검증 |
| 라이저도 / 개통도 | `ICT_Twin_Riser_…png`, `ICT_Twin_Topology_…svg` | 표제란: 사업장·작성일·「현행화 기반 자체 작도」 |
| 현장 사진 | `ICT_Twin_Photos_YYYYMMDD.zip` | `설비ID_01_전경.jpg` … + 사진목록.csv |
| 초안 백업 | `TwinX_간이현행화_초안_YYYY-MM-DD.json` | 다른 PC에서 「초안 불러오기」 |

- 설비ID: `건물코드-층코드-구분-순번` (예: `BD01-F07-REP-001`, 구분 REP 중계기 · RU 기지국 · OFD · PWR 전원 · EQ 기타)
- ADMIN에 올릴 파일명은 **영문**으로 유지합니다.

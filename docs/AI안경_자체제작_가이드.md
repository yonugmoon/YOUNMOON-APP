# AI안경 자체제작 가이드 — 설비 현행화 → AR 점검·진단

## 핵심 개념
AI안경은 결국 **① 카메라·마이크(입력) ② 화면·스피커(출력) ③ AI 두뇌(판단)** 의 조합입니다.
휴대폰에는 이 세 가지가 모두 들어 있으므로, **휴대폰으로 먼저 소프트웨어(업무 흐름)를 완성**하고
그다음에 입력·출력 장치만 안경 형태로 바꾸면 됩니다. 소프트웨어는 그대로 다시 씁니다.

```
[1차] 휴대폰 단독        → 휴대폰 = 카메라 + 화면 + AI 연결        (지금 이 앱)
[2차] 휴대폰 + 헤드마운트 → 휴대폰을 머리에 장착, 양손 자유     (앱의 👓 안경모드)
[3차] 자체제작 안경      → 안경 = 카메라/마이크/소형디스플레이, 휴대폰 = 처리 허브
```

---

## 1차 — 휴대폰 (앱: `AR_설비점검.html`)

### 목표: 설비 현행화 (설비대장과 현장을 일치시키기)
1. **설정** 탭: 점검자, 사업장, Gemini API 키(Google AI Studio에서 발급) 입력
2. **설비 현행화** 탭
   - 기존 설비대장을 엑셀에서 CSV로 저장해 **대장 CSV 가져오기**
     (열 이름 자동 인식: 설비ID/관리번호, 종류, 명칭, 제조사, 모델, 시리얼, 위치, 설치일)
   - 대장에 없는 설비는 **명판 촬영 → AI 자동입력** 으로 등록 (제조사·모델·시리얼·정격 자동 판독)
   - **QR 라벨 인쇄** → 설비에 부착 (QR 내용: `YM:설비ID`)
3. 현장에서 **AR 점검**으로 QR을 비춘 뒤 **✔ 현행화**(또는 음성으로 "현행화") → 실사 확인 일시와 확인자가 기록됨
4. 대장과 다르면 설비 정보에서 **불일치** 표시 후 수정
5. **현행화 결과 CSV**로 내보내기 → 기존 시스템에 반영

### QR 없이 시작하는 현행화 (🧠 실시간 AI 인식)
QR 라벨이 아직 없는 설비도 **AR 점검 화면에서 설비를 비추기만 하면** AI가 인식합니다.
- 설정한 간격(기본 4초)마다 화면을 AI에 보내 제조사·모델·시리얼·상태를 판독하고 설비 위치에 보라색 점선 상자를 표시
- **정확도 높이는 방식**: 여러 프레임 결과를 다수결로 합침(✓3/4 = 4번 중 3번 같은 값), 설비대장과 대조(시리얼 일치가 가장 강한 근거), 같은 모델이 여러 대면 자동 확정하지 않고 시리얼을 비추라고 안내, O↔0·I↔1 오독 보정
- 결과: **대장에 있음** → 자동으로 점검 시작 / **대장과 다름** → 차이 표시, "갱신"으로 대장 수정 / **대장에 없음** → AI 판독값이 채워진 신규 등록
- 화면이 거의 그대로이면 AI 호출을 멈춰 사용량 절약. 등록 후 QR 라벨을 붙이면 다음부터는 QR로 즉시 인식(인터넷·사용량 불필요)

### 건물·층·실 구조 보기와 설비 배치도
- 설비 위치를 **건물 / 층 / 실(공간) / 랙** 으로 나눠 저장(예전 "3F 전송실 R-05" 형식은 자동 분리)
- 설비 현행화 탭 **🏢 건물·층·설비** 보기: 건물 > 층 > 실 > 설비종류 > 설비 트리, 단계별 현행화율 표시
- **🗺 배치도**: 공간을 출입구에서부터 천천히 한 바퀴 동영상 촬영(20~40초 권장) → 영상에서 장면 10장을 뽑아 AI가 설비를 찾고 평면 위치를 추정
  - 대장 설비와 자동 매칭(라벨·시리얼), 미등록 설비는 보라 점선 → 탭하면 신규 등록(위치 자동 입력)
  - 위치는 손가락으로 끌어 보정, 촬영 영상도 함께 보관해 다시 볼 수 있음
  - 대장 위치가 다른 설비는 경고 → "대장 위치를 이 공간으로 수정"
- 한계: AI가 영상으로 추정한 **대략적 배치**(정밀 측량 아님). 정확한 좌표는 2차(ARCore/LiDAR 공간 스캔)에서 보완

### 랙 실장 분석 (무슨 장비가 어느 칸에)
- 설비 정보 → **🗄 랙 실장 분석**, 또는 AR 화면에서 랙 인식 후 **🗄 실장 분석**(음성 "실장")
- 사진 여러 장(전체 1장 + 위→아래 근접) 또는 위→아래 영상 → AI가 위에서 아래 순서로 장비·모델·기능·라벨·LED/표시값·경보 의심, 블랭크/빈 공간(증설 여유 U), 보이는 슬롯·카드 모듈을 판독
- **실장 장비를 대장에 반영** → 각 장비가 랙의 하위 설비(예: EQ-…-U03, "랙명 #4")로 등록
- 다시 분석하면 이전 결과와 비교해 추가/제거 장비 표시, 사라진 장비는 대장에 '불일치'로 기록
- 한계: 명판 글자가 작거나 유리문 반사가 있으면 모델명 판독 불가(지어내지 않고 "판독 불가"로 표시). 장비 뒷면·내부 카드는 보이게 찍어야 판독 가능

### 다음 단계: AR 점검·진단
- QR을 비추면 화면에 설비 정보와 점검항목이 겹쳐 표시됨(AR 오버레이)
- 항목마다 **정상 / 주의 / 불량** 판정 (버튼 또는 음성)
- 판단이 애매하면 **AI 진단**: 카메라 화면을 AI가 보고 LED·표시창 수치·부식·누액 등을 근거로 판정하고 조치를 권고
  → "적용"이라고 말하면 결과에 반영
- **완료** → 이력 저장, 보고서 인쇄/PDF, 점검결과 CSV
- 점검항목은 **설정 → 점검항목 편집**에서 회사 기준(예: TTA 점검표)에 맞게 바꿀 수 있음

### 음성명령 (핸즈프리)
`정상` `주의` `불량` `다음` `이전` `진단` `적용` `촬영` `현행화` `다시`(항목 다시 읽기) `완료`

### 설치·실행
- 카메라는 **HTTPS**에서만 동작합니다. GitHub Pages 주소로 접속하세요:
  저장소 Settings → Pages → Branch `main` / root 선택 →
  `https://<계정>.github.io/YOUNMOON-APP/AR_설비점검.html`
- 안드로이드 Chrome 권장 (음성명령·손전등 지원). 아이폰 Safari는 음성명령이 제한적입니다.
- 브라우저 메뉴 → **홈 화면에 추가** 하면 앱처럼 실행되고, 한 번 연 뒤에는 오프라인에서도 열립니다(AI 진단만 인터넷 필요).
- 데이터는 휴대폰 안(브라우저 저장소)에 저장됩니다. 주기적으로 **설정 → 백업** 하세요.

## 2차 — 휴대폰 + 헤드마운트 (저비용 시제품, 약 2~5만원)
| 부품 | 용도 | 비고 |
|---|---|---|
| 스마트폰용 VR 헤드셋(카메라 구멍 있는 제품) 또는 머리 장착 휴대폰 거치대 | 휴대폰을 눈앞에 고정 | 카메라가 가려지지 않는 제품 |
| 블루투스 이어셋(마이크 포함) | 음성명령·음성안내 | 현장 소음 대비 |
| 안전모 부착형 거치대(선택) | 현장 안전 규정 대응 | |

- 앱에서 **👓 안경모드** → 화면이 좌/우 두 눈용으로 나뉘고 가로 전체화면이 됨
- 조작은 음성명령으로, 필요하면 화면을 탭해 버튼 표시
- 이 단계에서 **어떤 정보를 시야에 띄워야 실제로 도움이 되는지** 현장 피드백을 모으는 것이 중요합니다

> ⚠️ 헤드셋은 주변 시야를 가립니다. 이동 중 사용 금지, 고정된 장비 앞에서만 사용하세요.

## 3차 — 자체제작 AI안경 (시제품 약 10~30만원)

### 구조
```
 [안경 프레임]                                  [휴대폰/서버]
  카메라 ─┐                                      이 앱(점검 흐름·DB)
  마이크 ─┼─ 소형 보드 ── Wi-Fi/BLE ──────────▶  AI (Gemini 등)
  스피커 ─┤   (ESP32-S3 / 라즈베리파이)  ◀──────  결과(텍스트·음성)
  디스플레이┘
```

### 부품 예시
| 구분 | 추천 부품 | 비고 |
|---|---|---|
| 두뇌 보드(초소형) | Seeed XIAO ESP32-S3 Sense | 카메라·마이크 포함, 엄지손톱 크기, Wi-Fi |
| 두뇌 보드(고성능) | Raspberry Pi Zero 2 W + Camera Module 3 | 리눅스, 영상 처리 여유 |
| 디스플레이 | 0.96~1.3" 투명/미니 OLED + 반사 프리즘(버드배스) | 한쪽 눈 HUD. 처음엔 OLED만 달아도 충분 |
| 음성 | 골전도 스피커 또는 블루투스 이어셋 | |
| 전원 | 3.7V Li-Po 500~1000mAh + 충전 모듈 | 안경다리에 배치 |
| 프레임 | 보안경 + 3D 프린팅 브래킷 | 산업안전 보안경 활용 권장 |

### 개발 순서
1. ESP32-S3에서 카메라 사진을 Wi-Fi로 전송하는 예제(Arduino `CameraWebServer`) 실행
2. 버튼(또는 음성 키워드)으로 사진 촬영 → 휴대폰/서버로 전송
3. 서버가 이 앱과 같은 AI 프롬프트(설비 판독·점검 진단)로 분석 → 결과 텍스트 반환
4. 결과를 OLED에 표시하고 음성으로 읽어줌
5. 1차 앱의 설비 DB(QR ID 체계, 점검항목, 이력 CSV)를 그대로 사용

> 브라우저(HTTPS 페이지)는 안경 보드의 `http://` 영상에 직접 접근할 수 없으므로,
> 3차에서는 앱을 사내 서버나 휴대폰 로컬에서 실행하거나 중계 서버를 둡니다.

### 상용 제품 대안
직접 만들기 전에 비교해 볼 만한 것: 카메라+AI 스마트글라스, 산업용 AR 헤드셋(RealWear 계열 등).
1·2차에서 업무 흐름을 검증하면 자체제작/상용 중 무엇이 맞는지 판단할 근거가 생깁니다.

## 확장 아이디어
- 사내 설비관리 시스템과 연동(API)해 CSV 대신 자동 동기화
- 점검 이력이 쌓이면 설비별 고장 경향 분석 → 예방정비
- 원격 지원: 현장 영상을 본사 전문가에게 실시간 공유
- 열화상 카메라 모듈 추가 → 단자 과열 자동 진단
